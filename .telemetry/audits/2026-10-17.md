## Padrões observados

- **Nomes:** nomes padrão do Meta Pixel (`ViewContent`, `Lead`, `Contact`, `Search`) enviados também como eventos GA4.
- **Centralização:** um wrapper `track()` envia ao mesmo tempo para `dataLayer.push`, `gtag('event')` e `fbq('track')`.
- **Configuração:** o ID vem da variável de ambiente `GOOGLE_ANALYTICS_MEASUREMENT_ID` por meio de uma server function (`src/lib/google-analytics.functions.ts`). No site publicado ela está definida como `G-31EFTQ7Q9H`.

## Observações (comportamento no site publicado)

1. A cada navegação interna chegam ao GA4 **2 hits de `page_view`** para a mesma URL: o manual (`analytics.ts:34`) e o do "Medição otimizada → mudanças no histórico" do GA4.
2. Esses `page_view` levam o **título da página anterior** (ex.: `/produto/...` aparece com o título "Colchões | Probel Store").
3. O primeiro `config` usa `page_path`, um parâmetro do Universal Analytics que o GA4 não lê como dimensão padrão.
4. `Search` envia `search_string`. O relatório de busca do GA4 lê `search_term`.
5. O mesmo componente envia `Contact` ou `Lead` conforme o botão. Os dois significam a mesma ação: clique no WhatsApp.
6. Nenhum evento leva o local do clique (`origem`), exceto o botão flutuante. A categoria do produto e o slug também não são enviados.
7. `dataLayer.push({event, ...})` duplica cada evento como objeto no estilo GTM, mas não existe container GTM.
8. A conversão do Google Ads **"Solicitar cotação"** (`ads_conversion_Solicitar_cota_o_1`) dispara ao **carregar /colchoes** e chama `www.google.com/measurement/conversion`. Os cliques em WhatsApp não acionam conversão no Google Ads.
9. `fbq` é chamado de forma opcional, mas o script do Meta Pixel não é carregado.
10. Não há Consent Mode configurado.

## Segunda auditoria: por que o Google não encontrou a tag (2026-10-17, tarde)

O domínio dos anúncios é **www.probelcolchoescanasvieiras.com.br**, servido pela **Vercel**. O `probel-dreamweaver-pro.lovable.app` é só o espelho da Lovable.

HTML entregue (`curl`, sem executar JS):

| URL | Servidor | `googletagmanager` no HTML | ID retornado pela server function |
|-----|----------|----------------------------|-----------------------------------|
| www.probelcolchoescanasvieiras.com.br | Vercel | 0 | `measurementId:null` |
| probel-dreamweaver-pro.vercel.app | Vercel | 0 | `measurementId:null` |
| probel-dreamweaver-pro.lovable.app | Cloudflare (Lovable) | 0 | `"G-31EFTQ7Q9H"` |

São duas causas independentes:
1. **Variável de ambiente ausente na Vercel.** `GOOGLE_ANALYTICS_MEASUREMENT_ID` existe só na hospedagem da Lovable, então o domínio dos anúncios **nunca carregou a tag**.
2. **Tag injetada só no cliente** (`document.createElement` num `useEffect`). O "Teste a conexão" lê o HTML entregue e não espera o React hidratar, então não acha a tag nem na Lovable.

**Correção:** snippet oficial renderizado no `<head>` pelo servidor (`src/routes/__root.tsx`), com o ID em `src/config/analytics.ts`, sem variável de ambiente.
